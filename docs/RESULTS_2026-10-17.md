## 3b. Separation probe on S08 (prompt v5)

The reader chose the new `separation` template. The harness built the target from the exact source conclusion:

`∃ T S g, (∀ x ∈ T, (∃ L, Tendsto (S x) atTop (𝓝 L)) ∧ (∀ x ∈ T, Tendsto (S x) atTop (𝓝 (g x))) → ContinuousOn g T) ∧ ¬ ((∀ x ∈ T, Tendsto (S x) atTop (𝓝 (g x))) ∧ ContinuousOn g T)`

GPT-6 Sol proved it on its first attempt with T = univ, S = 0 and g = 1, and Lean accepted the proof: `EVIDENCE-CHECKED`, schema bridge, 6 calls, $0.065. It abstained on the refutation, correctly noting that the negation is false.

This is the first accepted Lean evidence for a model-generated claim on a benchmark statement, but it does not confirm the known defect. The model's intended statement, "S converges to g and g is continuous", is wrong: the problem's g is constrained only through the implication, so even a correct formalization is satisfied by S = 0 and g = 1 while that intended statement fails. The separation therefore holds against a mis-stated reading, not because of the precedence error. The hand-written certificate `B82_weaker` separates correctly by choosing a divergent S against the intended reading "S converges, and convergence to g implies g is continuous". The finding remains unconfirmed, as designed: the claim's obligation requires a reviewer to check the model's intended statement, and that review would reject this one.

Lesson for the template: separation evidence is only as good as the intended statement. A reader instruction that the intended statement must keep the problem's own definitions, or a second check that a known-good formalization does not also separate, is the next refinement.

## 3c. Edit guard, negative controls and the first confirmed-shape evidence (prompt v6)

The separation template no longer accepts a free-form intended statement. The reader gives one edit to the source conclusion, an exact substring occurring once plus its replacement, and the harness builds the intended statement from it. Each edit is classified: `regrouping` (only parentheses change), `reordering` (same tokens, new order) or `rewrite` (content added or removed). Rewrites carry an explicit warning in the review obligation. On the real S08 text, the correct fix classifies as regrouping and the run-3b reading classifies as rewrite.

| Control | Expected | Reader | Edit | Evidence |
| --- | --- | --- | --- | --- |
| S08 (known defect) | separation | `wrong_strength`, separation | regrouping, identical to the hand-written fix `I82` | UNRESOLVED in 2 attempts; `EVIDENCE-CHECKED` with 3 repairs |
| S05 (clean) | nothing accepted | spurious `domain` claim, separation | rewrite (flagged) | UNRESOLVED; the writer judged the target false |
| S07 (clean) | nothing accepted | spurious `wrong_strength` claim, equivalence | none | UNRESOLVED; both directions declined |
| S12 (clean) | nothing accepted | no claim | none | none |

The accepted S08 proof chooses T = {0}, S x n = n and g = 0, proves that the sequence n does not converge, and concludes that the source conclusion holds vacuously while the regrouped statement fails. This is the same argument as the earlier hand-written certificate `B82_weaker`, produced and checked automatically from a reader-proposed edit. It is Lean-verified evidence of a separation in logical form under the schema bridge; the finding remains unconfirmed until a reviewer discharges the regrouping obligation. Re-proving the stored claim with three repairs cost $0.071 and no new reader call.

Two of three clean controls drew a reader suspicion, and none produced accepted evidence: the reader is noisy and formal checking filtered it, on this very small sample.

The first two rejected S08 attempts failed on name resolution: short names such as `Tendsto` and `atTop` were unknown because the item's `open` declarations applied to the target but not to the proof. The harness now checks proofs under the same open declarations and records them as `proof_opens`, and the writer prompt says so (prompt v7). This changes name resolution only, not the proposition being proved.

## 3d. Target elaboration check and run-to-run variation (prompts v7 and v8)

On the full S08 pipeline with prompt v7, the reader again proposed a regrouping separation, but its witness field contained prose (`(T : Set ℝ) (S : ℝ → ℕ → ℝ) (g : ℝ → ℝ); take T = {0}, …`). The target itself could not parse, so two writer calls were spent on an impossible goal. Every claim's target is now elaborated by Lean before any proof call, and a target that fails is recorded as a rejected candidate with Lean's error. The reader prompt now says witnesses contain only binders (prompt v8).

On the v8 run the proof was accepted on its first attempt (5 calls, $0.041), using the same divergent-sequence witness. The reader's edit this time was `→ ContinuousOn g T` to `∧ ContinuousOn g T`, which the guard classified as a rewrite. That edited statement is not a faithful reading: it requires the free variable g to be the limit of S, which the problem never asserts of an arbitrary g. A reviewer should reject this edit, and the obligation text told them to check it closely. The accepted evidence that does match the defect is the regrouping separation from section 3c.

Across four full S08 runs, the reader raised a claim each time, used separation three times, and produced the correct regrouping twice. Reader output varies between runs, so a study should either sample several reader runs per item or report this variance.

## 3e. Lint-derived claim on S08, no reader (October 18)

The deterministic precedence lint now turns a `strong` finding with a unique suggested edit into a separation claim without any reader call: type `precedence`, schema bridge, `claim_source: lint`, the lint's regrouping as the edit. Witnesses come from the parse tree: the theorem binders whose names the conclusion uses, closed under the binders their types need. On 1982 B5 that keeps `(T : Set ℝ) (S : ℝ → ℕ → ℝ) (g : ℝ → ℝ)` and drops `hT` and `hS`, the same witnesses the reader chose. The `lint-audit` command runs these claims separately from reader claims.

| Check | Cost | Result |
| --- | --- | --- |
| Claim construction and target elaboration, S08 (v4.35.0) and `putnam_1982_b5` (v4.33.1) | free | both build a regrouping separation and elaborate |
| Replay of the section 3c proof against the lint claims (the targets differ from 3c only by one line break) | free | accepted in both environments, axioms `propext`, `Classical.choice`, `Quot.sound` |
| GPT-6 Sol writer on the S08 lint claim, `study-triage` limits (1 repair, at most 4 calls) | 2 calls, $0.039 | `EVIDENCE-CHECKED` on the first attempt; refutation declined, correctly calling the negation false |

The new proof uses the same witness as before (T = {0}, S x n = n, g = 0), but it discharges the source conclusion with `continuousOn_const` rather than by vacuity. The path from lint to Lean-checked evidence is now deterministic up to the writer, and on this one known defect it needs no reader. That is one development item, not a measurement: the lint covers a single bug class, and the finding remains unconfirmed until a reviewer discharges the regrouping obligation.

## 3f. Reader self-consistency, k = 3 (October 18)

An optional `limits.reader_samples` samples the reader k times, each with its own cache key. Claims from different samples that share a type or a location form a cluster. A cluster is kept when a majority of samples contribute to it, and its representative prefers regrouping, reordering or binder-move separations over rewrites. Profiles without the key keep their fingerprints. The check used `configs/study-reader-k3.toml` (reader only).

| Control | Samples with a claim | Kept clusters | Representative | Cost |
| --- | --- | --- | --- | --- |
| S08 (known defect) | 3 / 3 | 1 (support 3) | separation, rewrite (`wrong_strength`) | 3 calls, $0.052 |
| S05 (clean) | 2 / 3 | 1 (support 2) | spurious `domain` equivalence | 3 calls, $0.041 |

On this tiny sample, self-consistency did not do what it was meant to. On S08, all three samples raised the suspicion, but none proposed the regrouping, so the preference rule had nothing better to choose. On S05, the spurious suspicion recurred in two of three samples and survived the majority rule. Reader errors look correlated across samples, not independent, so majority voting at k = 3 is not an effective filter here, and it triples reader cost. The deterministic lint (section 3e) is the more reliable source of the S08 regrouping. Sampling stays available as an option; it is not recommended for the study on this evidence.

## 3g. Signature-level separation (prompt v9, October 18)

The new `hypothesis_separation` template applies one edit to exactly one hypothesis type. It tests that some instance satisfies the edited hypotheses but not the source hypotheses, using the instance bridge. The harness derives witnesses and hypotheses from the parse tree. A hypothesis is a named binder that no other part of the signature refers to, and `Type*` witnesses are taken in `Type`. A conclusion edit that only quantifies a sub-term over an existing theorem binder is now classified as `binder_move` rather than `rewrite`.

| Check | Cost | Result |
| --- | --- | --- |
| S03 (`putnam_2016_a5`, extra hypotheses), hand-written candidate and proof: drop the two non-generation conjuncts, witness `Multiplicative (ZMod 3)` | free | target elaborates and is accepted |
| S11 (`putnam_2004_a4`, x outside ∃), hand-written candidate and proof: quantify the product identity over `x` | free | classified `binder_move`; target elaborates and is accepted (schema: `avals` abstract, n = 1) |
| S03, v9 reader and writer, at most 1 claim and 1 repair (`configs/check-triage.toml`) | 4 calls, $0.061 | the reader chose `hypothesis_separation` with the same edit as the hand-written candidate; `EVIDENCE-CHECKED` after one repair, using the trivial group with g = h = 1; refutation declined |
| S11, v9 reader only | 1 call, $0.015 | the reader proposed the same binder-move separation as the hand-written one; no writer call, since the target was already shown provable |

The S03 evidence shows that the source hypotheses exclude a group the informal wording admits. A reviewer must confirm that the trivial group, or another witness, is admissible in the official problem, and that removing the conjuncts adds or removes nothing else. The edit is classified `rewrite` because it removes content, and the obligation says so. The S11 evidence is schema-level, like the earlier hand-written certificate: it abstracts `avals` and does not show a truth-value difference for the actual product. The hand-written candidates and proofs are development validation, not model output, and are labelled as such in `experiments/signature-separation-free`.

## 3h. Fix-history pairs (free, October 18)

`yamalemma fix-pairs` takes every statement-touching upstream commit since a date. For each problem changed by a commit, it writes the file before and after that commit, with hashes and one provenance group per pair (`problem@commit`). It then ingests both versions with answer substitution and checks that each statement elaborates in the pinned environment. Problems in a given selection, here the held-out 40, are skipped, so no pipeline step touches them. No model was called.

Run: PutnamBench at `a635813`, commits since 2025-06-01, `lean-putnambench`, output in `experiments/fix-pairs-a635813`.

| | Count |
| --- | --- |
| Changed problem files across 20 commits | 166 |
| Skipped: held-out problem | 11 |
| Skipped: file added or removed | 12 |
| Pairs written | 143 |
| Pairs from fix-like commits (subject says fix, correct or wrong; excludes build, deprecation and highlighting commits) | 33 |
| Fix-like pairs where both versions elaborate and the statement changed | 10 |
| Fix-like pairs blocked by the target-syntax allowlist | 22 |
| Fix-like pairs blocked as executable syntax | 1 |
| Pre-fix files that do not parse (all from non-fix commits, mainly the 91-file deprecation commit) | 84 |

The 10 usable pairs are `putnam_2010_a3`, `putnam_1967_b6`, `putnam_2011_a1`, `putnam_1963_a6`, `putnam_1977_a2`, `putnam_1977_b6`, `putnam_1980_a4`, `putnam_2003_b5`, `putnam_2019_a5` and `putnam_2019_b5`.

Every fix-like pre-fix file parses in the pinned environment. The expected obstacle, an adapter for older toolchains, is therefore not the main blocker for this stratum. The main blocker is Yamalemma's own target-syntax allowlist (`proof_syntax.json`), which rejects common notation such as `∑'`, `∫ x in a..b`, `‖·‖`, `ℙ`, `∅` and `∩`. Widening that list is a trust-boundary decision. Each added syntax kind should be a notation, not an elaborator or tactic hook. A maintainer fix is evidence for review, not a label: both versions of each pair still need independent review before any recall number exists.

## 6. Bugs found and fixed during these runs

- A variable named `text` hid the `text()` helper in `ingest_source` when answer substitution was on.
- `source_sha256` recorded the original file instead of the substituted text, so the harness rejected substituted items. It now hashes the checked text, and `original_source_sha256` keeps the upstream hash.
- The proof writer had no way to decline; declines were parsed as proofs and repaired. The writer schema now has an explicit abstention.
- Statement-level probes asked the writer for full Putnam solutions. A source-bound `separation` template now tests the exact source conclusion against a proposed intended statement.
